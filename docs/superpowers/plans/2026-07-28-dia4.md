# dia4 — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Um Worker que serve React + API Hono lendo do Neon, onde cada Pull Request ganha banco isolado, migrations aplicadas, testes rodados e uma URL de preview própria — destruídos quando o PR fecha.

**Architecture:** Um único Cloudflare Worker serve os assets do React (build do Vite em `dist/client`) e responde `/api/*` via Hono. O acesso ao Postgres no runtime usa o driver HTTP do Neon; `drizzle-kit` e o seed rodam em Node no runner do GitHub Actions. Cada PR cria uma branch Neon homônima e publica uma versão do Worker com `--preview-alias`, carregando a `DATABASE_URL` daquela branch via `--secrets-file`.

**Corrigido em 28/07/2026:** este plano dizia que a `DATABASE_URL` fica "presa à versão". Está errado — secrets são do Worker e vazam para o `wrangler deploy` seguinte, o que quebrou produção. Por isso o deploy de produção também passa `--secrets-file`. Ver a seção de secrets no spec.

**Tech Stack:** Cloudflare Workers (wrangler 4.111), Hono, React 19 + Vite, Drizzle ORM + drizzle-kit, Neon Postgres (`@neondatabase/serverless`), Vitest, GitHub Actions, `neonctl`, `gh`.

## Global Constraints

- Node 24 local e no runner (`actions/setup-node@v4` com `node-version: 24`).
- Cloudflare account ID: `592d4fe686ebfceddb1d804472769efe`.
- Org Neon: `org-restless-hill-40735252`.

`tests/students.test.ts`:

```ts
import { neon } from "@neondatabase/serverless";
import { beforeAll, describe, expect, it } from "vitest";
import app from "../worker/index";

const env = { DATABASE_URL: process.env.DATABASE_URL! };

beforeAll(() => {
  if (!env.DATABASE_URL) throw new Error("DATABASE_URL ausente");
});

async function get() {
  const res = await app.request("/api/students", {}, env);
  return { res, body: (await res.json()) as { columns: string[]; rows: unknown[] } };
}

describe("GET /api/students", () => {
  it("devolve as linhas do seed", async () => {
    const { res, body } = await get();
    expect(res.status).toBe(200);
    expect(body.rows).toHaveLength(3);
    expect(body.rows.map((r) => (r as { name: string }).name)).toContain("Luis");
  });

  it("as colunas declaradas batem com as colunas reais do postgres", async () => {
    const { body } = await get();
    const sql = neon(env.DATABASE_URL);
    const real = await sql`
      SELECT column_name FROM information_schema.columns
      WHERE table_name = 'students' AND table_schema = 'public'
    `;
    const noBanco = (real as { column_name: string }[]).map((r) => r.column_name).sort();
    const naApi = body.columns
      .map((c) => c.replace(/[A-Z]/g, (m) => `_${m.toLowerCase()}`))
      .sort();
    expect(naApi).toEqual(noBanco);
  });
});
```

O segundo teste é o coração do projeto: `columns` vem do schema Drizzle, `noBanco` vem do Postgres. Se alguém alterar `schema.ts` sem gerar a migration, os dois divergem e o PR fica vermelho. A conversão camelCase → snake_case existe porque Drizzle expõe a chave TypeScript (`createdAt`) e o Postgres tem `created_at`.

- [ ] **Step 1: Reescrever `src/App.tsx`**

Nenhum cabeçalho escrito à mão — é isso que faz uma migration sozinha mudar a UI.

```tsx
import { useEffect, useState } from "react";

type Payload = { columns: string[]; rows: Record<string, unknown>[] };

export default function App() {
  const [data, setData] = useState<Payload | null>(null);
  const [erro, setErro] = useState<string | null>(null);

  useEffect(() => {
    fetch("/api/students")
      .then((r) => (r.ok ? r.json() : Promise.reject(new Error(`HTTP ${r.status}`))))
      .then(setData)
      .catch((e: Error) => setErro(e.message));
  }, []);

  if (erro) return <p>Erro ao carregar: {erro}</p>;
  if (!data) return <p>Carregando…</p>;

  return (
    <main style={{ fontFamily: "system-ui", padding: "2rem" }}>
      <h1>dia4</h1>
      <table cellPadding={8} style={{ borderCollapse: "collapse" }}>
        <thead>
          <tr>
            {data.columns.map((c) => (
              <th key={c} style={{ borderBottom: "2px solid #333", textAlign: "left" }}>
                {c}
              </th>
            ))}
          </tr>
        </thead>
        <tbody>
          {data.rows.map((row, i) => (
            <tr key={i}>
              {data.columns.map((c) => (
                <td key={c} style={{ borderBottom: "1px solid #ccc" }}>
                  {String(row[c] ?? "")}
                </td>
              ))}
            </tr>
          ))}
        </tbody>
      </table>
    </main>
  );
}
```

```yaml
  pull-requests: write

jobs:
  preview:
    runs-on: ubuntu-latest
    env:
      NEON_API_KEY: ${{ secrets.NEON_API_KEY }}
      NEON_PROJECT_ID: ${{ secrets.NEON_PROJECT_ID }}
      BRANCH: pr-${{ github.event.number }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - run: npm ci

      - run: npm run typecheck

      - name: Criar ou reutilizar a branch Neon
        id: neon
        run: |
          if ! npx neonctl branches get "$BRANCH" --project-id "$NEON_PROJECT_ID" >/dev/null 2>&1; then
            npx neonctl branches create \
              --project-id "$NEON_PROJECT_ID" \
              --name "$BRANCH" \
              --expires-at "$(date -u -d '+7 days' +%Y-%m-%dT%H:%M:%SZ)"
          fi
          URL=$(npx neonctl connection-string "$BRANCH" --project-id "$NEON_PROJECT_ID" --pooled)
          echo "::add-mask::$URL"
          echo "url=$URL" >> "$GITHUB_OUTPUT"

      - name: Aplicar migrations
        env:
          DATABASE_URL: ${{ steps.neon.outputs.url }}
        run: npx drizzle-kit migrate

      - name: Seed
        env:
          DATABASE_URL: ${{ steps.neon.outputs.url }}
        run: npm run seed

      - name: Testes de integração
        env:
          DATABASE_URL: ${{ steps.neon.outputs.url }}
        run: npm test

      - run: npm run build

      - name: Publicar versão de preview
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          DATABASE_URL: ${{ steps.neon.outputs.url }}
        run: |
          jq -n --arg u "$DATABASE_URL" '{DATABASE_URL:$u}' > secrets.json
          npx wrangler versions upload \
            --preview-alias "$BRANCH" \
            --secrets-file secrets.json \
            --message "PR #${{ github.event.number }}"
          rm secrets.json

      - name: Comentar a URL no PR
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          gh pr comment ${{ github.event.number }} --edit-last --create-if-none --body "$(cat <<EOF
          **Preview:** https://${BRANCH}-dia4.<subdominio>.workers.dev

          Banco isolado na branch Neon \`${BRANCH}\` (migrations aplicadas, seed rodado).
          Commit: \`${{ github.event.pull_request.head.sha }}\`
          EOF
          )"
```

O `--expires-at` de 7 dias é rede de segurança: se o job de cleanup falhar, a branch some sozinha e não ocupa vaga no limite do plano. O `::add-mask::` impede que a connection string apareça em qualquer log subsequente. O `secrets.json` é criado e apagado dentro do mesmo step, e nunca sai do runner.

### Task 9: Workflows de cleanup e de produção

**Files:**
- Create: `.github/workflows/pr-cleanup.yml`, `.github/workflows/deploy.yml`

**Interfaces:**
- Consumes: os quatro secrets (Task 7).
- Produces: nada consumido por tasks posteriores.

- [ ] **Step 1: Criar `.github/workflows/pr-cleanup.yml`**

```yaml
name: PR Cleanup

on:
  pull_request:
    types: [closed]

permissions:
  contents: read

jobs:
  cleanup:
    runs-on: ubuntu-latest
    steps:
      - name: Apagar a branch Neon do PR
        env:
          NEON_API_KEY: ${{ secrets.NEON_API_KEY }}
          NEON_PROJECT_ID: ${{ secrets.NEON_PROJECT_ID }}
        run: |
          npx neonctl branches delete "pr-${{ github.event.number }}" \
            --project-id "$NEON_PROJECT_ID" || echo "branch ja inexistente, seguindo"
```

Roda tanto em merge quanto em fechamento sem merge. O `|| echo` evita job vermelho quando a branch já expirou pelo `--expires-at`.

Nada da Cloudflare precisa de limpeza: versões não promovidas simplesmente deixam de ter alias apontando.

- [ ] **Step 2: Criar `.github/workflows/deploy.yml`**

```yaml
name: Deploy produção

on:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - run: npm ci

      - run: npm run typecheck

      - name: Connection string de produção
        id: neon
        env:
          NEON_API_KEY: ${{ secrets.NEON_API_KEY }}
          NEON_PROJECT_ID: ${{ secrets.NEON_PROJECT_ID }}
        run: |
          URL=$(npx neonctl connection-string --project-id "$NEON_PROJECT_ID" --pooled)
          echo "::add-mask::$URL"
          echo "url=$URL" >> "$GITHUB_OUTPUT"

      - name: Aplicar migrations em produção
        env:
          DATABASE_URL: ${{ steps.neon.outputs.url }}
        run: npx drizzle-kit migrate

      - run: npm run build

      - name: Deploy
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
        run: npx wrangler deploy
```

Sem `--parent` nem nome de branch: `connection-string` sem argumento usa a branch padrão do projeto, que é a de produção.

Note que o deploy de produção **não** roda `npm test` — os testes de integração precisam de um banco descartável, e apontá-los para produção apagaria os dados no seed. A cobertura de teste acontece no PR, antes do merge.


Isso registra o environment. Se depois quiser exigir aprovação manual antes de cada deploy, configure revisores em Settings → Environments → production.

```bash

git commit -m "ci: cleanup de branch neon e deploy de producao"

```
